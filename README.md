> [!IMPORTANT]
> **Simulation Harness Disclosure**: `agent-durability-bench` is a **synthetic fault-injection simulation harness**, not a benchmark of live third-party servers. It executes deterministic child subprocesses, injects physical OS `SIGKILL` (`kill -9` / `taskkill /F /T`) across four execution windows (`PROMPT`, `EXEC`, `WRITE`, `VERIFY`), and models how four persistence archetypes (**Step-Level Atomic WAL**, **Superstep Snapshot**, **Unpersisted In-Memory Loop**, and **Unmanaged Script**) behave on restart. Non-LetItLoop adapters model architectural checkpointing boundaries rather than running external database servers or clusters.

---

## What This Harness Tests

When an agent or batch pipeline crashes mid-run (`SIGKILL`, OOM, or spot preemption), three failure modes matter:
1. **Duplicate Step Re-Execution (`W_token`)**: Does the resumed process skip already-completed steps or re-run from the start of the active node/script?
2. **State File Integrity (`C_fail`)**: Does an interrupted write leave corrupted or unparseable state on disk?
3. **Resumption Overhead (`T_resume`)**: How quickly does the runner reconstruct completed step state upon restart?

## Quickstart

```bash
git clone https://github.com/sdageltc/agent-durability-bench.git
cd agent-durability-bench
pip install -e .

# Run test suite and subprocess fault-injection tests
pytest tests/ -v

# Run a single trial on the Atomic WAL archetype
python -m harness.runner --framework atomic_wal --signal SIGKILL

# Run the 4-window x 4-archetype simulation matrix and export JSON/Markdown
python -m harness.runner --compare all --export-json results/leaderboard.json --export-markdown docs/index.md
```

| 🥈 | **`Periodic Snapshot Graph (Superstep Checkpointing)`** | `100.0%` | `14.5%` *(modeled intra-node re-run)* | `~50 ms` *(modeled)* | 🔴 NON-CONFORMANT |

| **4** | **`Unmanaged Script Execution (Raw Python CLI)`** | `0.0%` | `100.0%` *(full restart)* | `N/A` | 🔴 NON-CONFORMANT |

> [!NOTE]
> Modern agent frameworks (LangGraph `SqliteSaver`, CrewAI `@persist` Flows, DBOS SQLite, Google ADK `DatabaseSessionService`, OpenAI Agents SDK `SQLiteSession`) provide built-in persistence when configured. The `In-Memory Event Loop` row above represents unpersisted in-memory execution without a checkpointer enabled.
