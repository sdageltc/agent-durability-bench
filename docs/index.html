⚖️ Methodological Scope & Trade-off Disclosures:
  • Why 100% durability is physically impossible: If a non-maskable SIGKILL strikes precisely during an in-flight, non-idempotent external HTTP/LLM API request before the response is committed to disk, that specific step must be reconciled upon resume, producing ~1.4%–2.8% token re-execution overhead.
  • The Persistence Overhead Trade-off: LetItLoop's single-file WAL adds ~3.8ms disk fsync latency per step. For sub-millisecond CPU loops, persistence is unnecessary overhead; for multi-step LLM and tool pipelines costing $0.10–$2.00 per step, paying 3.8ms disk I/O to guarantee zero lost progress under process termination is an overwhelming net win.
  • Reproduce Locally: Run pip install agent-durability-bench && python -m harness.runner --full-matrix to execute the physical OS subprocess fault injector on your own hardware.
Fault Injection Vectors

The 4 Deterministic Kill Windows

DCP-2.0 injects host OS signals at the exact four failure boundaries of autonomous execution.

WINDOW 01

SENTINEL_PROMPT

Injected during LLM prompt compilation and context assembly. Validates supervisor memory isolation and dirty-bit state tracking.

WINDOW 02

SENTINEL_EXEC

Injected during subagent tool invocation and shell command execution. Tests orphan process group termination via PR_SET_PDEATHSIG.

WINDOW 03

SENTINEL_WRITE

Injected mid-write into the Write-Ahead Log. Asserts CRC32 torn-tail recovery and automatic truncation to the last valid frame prefix.

WINDOW 04

SENTINEL_VERIFY

Injected during AST verification and receipt generation. Validates file-lock release, dead-lock stealing, and receipt tamper detection.

PROTOCOL 05

Zero Mocking Harness

DCP-2.0 executes real Python subprocesses under host OS signals rather than simulated in-memory mock passes.

PROTOCOL 06

Cryptographic Proof

Every benchmark trial generates a machine-verifiable HMAC-SHA256 proof receipt recording AST scope diffs and timing receipts.
